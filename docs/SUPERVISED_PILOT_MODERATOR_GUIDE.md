# ResearchOps Agent Supervised Pilot 主持指南

> 版本：`supervised-pilot-moderator-v1`
> 适用范围：正式外部 pilot 前的 1–2 人监督预试运行
> 证据状态：操作与人因排障；不是正式外部验证

## 1. 主持目标与硬边界

本阶段只核验招募、同意、页面、计时、反馈、撤回和技术事件记录是否可操作。每人按服务中冻结的顺序完成同一套 6 个 prepared public tasks；所有结果固定为：

```text
pilot_phase=supervised_pretest
qualifying_external_pilot=false
external_validation_claim_allowed=false
professional_correctness_assessed=false
```

当前 `pilot_pack.supervised_v6.json` 绑定 Kimi Models-preflight successor v5 candidate，
原样沿用 historical `pilot_pack.supervised_v5.json` 的 6 道公开任务、翻译与 DeepSeek
Provider，但不继承任何旧参与者或结果。历史 v5 pack 继续绑定 predecessor v4
candidate，不得改写。Kimi preflight 为 `implemented_offline_tested_not_run`；未 live 预检、
未在线运行，Kimi 未注册为 pilot Provider。
目标人数固定为 1；不得跨 campaign 聚合，也不得据此声称模型质量、外部验证或未知分布
泛化。当前尚未授权或执行该 pack 的在线运行。

主持人不能评价答案正确性、提示期望行为、解释任务或替参与者作答。预试记录不能计入正式 pilot 的人数、20 次交互、覆盖或成功率。

全程禁止录音、录像、录屏、自动会议转写和逐字记录。不得要求参与者提供 API Key，不得使用其个人、患者、机构或未公开研究数据。

## 2. 场次前检查

在邀请参与者进入前逐项确认：

- [ ] 招募检查表已完成，参与者符合资格且不属于排除对象。
- [ ] 联系方式、排期和补偿信息保存在 pilot 系统之外；场次材料中只有随机假名 ID。
- [ ] 使用 supervised 专用 campaign/session，未复用正式 pilot session。
- [ ] 固定 protocol、同意文案、6 题顺序、Provider/model 和部署版本已记录。
- [ ] Candidate commitment 为 `105b7def81148566219673fd40e88e392674070656c72a17cbcf60405165dffc`。
- [ ] Task pack 为 `pilot_pack.supervised_v6.json`，Provider 仍为 DeepSeek。
- [ ] Provider Key 只在服务端 secret 中；浏览器和参与者无需输入 Key。
- [ ] 没有启用录音、录像、录屏或会议自动转写。
- [ ] 单场记录模板已经创建，但不含姓名、邮箱、机构、IP 或其他直接身份信息。
- [ ] 已准备退出、撤回和技术故障处理路径。
- [ ] 若机构要求 IRB/伦理判定，所需判定已在招募前完成。

任一项不能确认时，不开始场次。

## 3. 固定开场词

主持人逐字朗读：

> 感谢你参加 ResearchOps Agent 的监督预试运行。本次预计 40–50 分钟，只用于检查邀请、同意、页面操作和反馈流程是否清楚，不是正式外部验证，也不评估统计、医学或科研结论是否专业正确。你将使用项目准备的公开数据完成 6 个任务，并评价回答是否看得懂、是否对下一步有帮助、是否遗漏信息或引起安全担忧。
>
> 请不要输入或说出姓名、邮箱、单位、API Key、患者信息、你自己的研究数据或任何保密内容。本场不会录音、录像、录屏或使用自动转写。我只会记录去标识的操作观察和技术事件，不保存答案正文或逐字引语。
>
> 你可以跳过任何题目或随时撤回参与，无需说明理由，也不会因此失去已经说明的固定补偿。撤回不是普通的“完成”或“关闭页面”；正常完成后直接关闭页面即可。我的任务是帮助你使用页面，不会解释题目或答案，也不会提示应该选择哪项反馈。请先阅读页面上的同意说明；只有你主动同意后我们才继续。

等待参与者自行完成同意操作。主持人不得代点、预勾选或以口头同意替代页面中的主动确认。

## 4. 固定操作说明

同意完成后逐字朗读：

> 页面会依次显示任务、授权上下文和 Agent 回答。请按自己的理解操作。回答出现后，请评价它是否易懂、是否有助于下一步，以及你是否发现明显问题、信息遗漏或安全担忧。如果没有把握，请如实选择低信心或需要专家复核。安全拒绝或等待人工审批本身不一定是错误。

随后让参与者自行完成冻结顺序中的 6 个任务。不得临场选择“更容易”或预期表现更好的题。

## 5. 允许和禁止的主持回应

允许使用的中性回应：

- “这个按钮用于继续当前页面流程。”
- “请按你自己的理解填写。”
- “如果没有把握，可以选择低信心或需要专家复核。”
- “你可以跳过这题，或者随时撤回参与；正常完成后直接关闭页面即可。”
- “我先把它记录为技术事件，不会替你重新选择答案。”
- “这次预试只检查页面和评价流程；请记录是否看懂、是否有用，专业正确性不在本次判断范围内。”

禁止的回应或行为：

- 解释数据、统计术语、因果含义、答案内容或该题为什么这样设计；
- 使用“答对了”“模型应该拒绝”“这个结果可信”等判断；
- 建议选择 Yes/No、提高或降低置信度；
- 展示 machine score、golden、后台记录或其他参与者反馈；
- 因负面反馈、Provider 失败或不满意回答而重跑、换题；
- 在场次中修改 prompt、Provider/model、工具 schema、scorer、任务或反馈字段；
- 把参与者口述内容逐字抄录，或复制 Agent 答案正文。

参与者询问领域或统计问题时，使用固定回复：

> 我不能在本次预试中解释任务或判断答案正确性。请只记录你是否看懂、是否觉得有助于下一步，以及是否需要专家复核。

## 6. 观察记录方法

主持人只记录以下内容：

- 页面或按钮是否被找到；
- 操作在哪一步停滞；
- 是否出现技术错误、等待过久或状态不一致；
- 参与者是否完成、跳过或撤回；
- 参与者口头观察的去标识、概括性摘要。

合规摘要示例：

> 参与者表示“需要专家复核”的含义第一次阅读时不够清楚；主持人未解释答案，仅重申可以按自身把握选择。

不合规记录包括姓名、单位、研究项目、逐字长引语、答案内容、Provider 原始错误正文、traceback、IP、路径、Key 或任何可能重识别参与者的信息。

## 7. 故障、跳过和撤回

出现技术故障时：

1. 不重跑同一分配，不临场换题；
2. 将任务标记为 `technical_event` / non-qualifying；
3. 只记录稳定事件代码、发生阶段、可见影响和是否恢复，不保存原始错误正文；
4. 若疑似泄露、越权、审批绕过或错误数据绑定，立即停止整场并通知技术负责人。

参与者跳过时，记录 `skipped_by_participant`，不追问理由。参与者撤回时：

1. 立即停止场次并撤销 session；
2. 不询问撤回理由；
3. 按协议触发 7 天内删除流程；
4. 按预先披露的固定补偿规则处理，不把补偿与继续参与挂钩。

撤回后，可用性反馈和普通运行 telemetry 不再计入可用性指标；为保护参与者所必需的去标识安全事件和最小审计记录可能继续保留，并继续阻断安全门禁。主持人不得把这一安全例外描述为参与者反馈仍被用于可用性评价。

## 8. 固定结束语

完成或正常提前结束时逐字朗读：

> 本次监督预试到此结束。谢谢你帮助我们检查操作流程。你的记录只会作为去标识的人因和技术排障材料，不会被称为正式外部验证，也不会用于判断专业正确性。请不要基于今天看到的回答作出科研、临床或其他实际决策。如果之后希望撤回，请使用邀请时提供的联系渠道，无需说明理由。

页面显示“已完成”后，主持人应明确说明参与者可以直接关闭页面，不要打开撤回折叠区或点击撤回按钮；只有参与者明确表示希望排除已提交反馈并请求删除参与者级数据时，才由参与者本人执行撤回。

## 9. 场次后处理

- [ ] 完成单场记录模板，确认无直接身份信息、API Key、IP、答案正文或逐字引语。
- [ ] 联系/补偿表继续与 pilot 数据分离。
- [ ] 技术或安全事件已使用独立事件 ID 关联，未复制敏感正文。
- [ ] 所有任务保持 `qualifying_external_pilot=false`。
- [ ] 未把 supervised 结果并入正式 pilot summary。
- [ ] 未修改锁定 prompt、scorer、工具 schema 或 candidate 源码。

预试可以推动主持文案、按钮和页面说明改进，但必须在本轮结束后创建新版本再核验。观察到的模型行为问题只能登记为后续候选问题；如确需修改锁定内容，必须另建 candidate、生成新 commitment 和新 campaign，不能继续调优当前锁定 prompt。
