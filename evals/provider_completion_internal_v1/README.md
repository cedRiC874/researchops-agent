# T6-B-Internal v1

Explicit, developer-known synthetic telemetry validation. This is not an external
campaign, independent review, unseen evaluation or model-quality benchmark. The
old external milestone and STATUS/T7 remain open; Depth-60 remains 20/60.

## Executable contracts

- `protocol_v1.json` and its fixed-value schema: the approved internal_30 limits.
- `cases_v1.json`: 30 ordered, unique synthetic cases, full UTF-8 input and per-input
  digest, expected `completed`, cap 512. No target-Provider authoring/screening calls.
- `case_origin_v1.json`: internally authored, developer-known, bounded exact-string
  comparison against repository eval JSON/JSONL. It is not semantic/global novelty
  or external-unseen evidence. The user must still approve the final task freeze.
- `pricing.pending.json`: deliberately cannot pass admission. Its values are not
  filled with a historic price and called current official evidence.
- Authorization/freeze field sets and semantics are enforced by
  `researchops_internal_telemetry.admission` and `contract`; budget semantics by
  the existing pure `_CampaignBudget`, not its external-owner admission wrapper.
- Record semantics use the existing mapper/sanitizer. Internal artifact fields,
  exact denominator, event order, timing and budget projections are independently
  replayed by `researchops_internal_telemetry.verify`.

The new source manifest is create-once and source-only. It includes executable
source, eval/config/policy inputs, dependency locks, pyproject and the root probe
receipt read by the mapper. It excludes its own generated bytes. Old v11 bytes
are never overwritten to validate this new tree.

## Runtime boundary

Supported entry: `python -m researchops_internal_telemetry.run`. The CLI requires
freeze and authorization files, the exact explicitly user-approved digest, and
`--confirm-online`. No root, transport, Key loader, store-path or bypass option is
exposed. No runnable authorization is supplied in this directory.

The approval model is a real user's explicit approval delivered by the trusted
local operator. Matching local JSON/digests is not independent identity proof,
an external signature, trusted-launcher attestation or admin-rollback resistance.

Committed source bytes, loaded origins/locked versions, authorization window and
fixed environment/store must validate before a new exclusive winning claim. Only
then can the process read `DEEPSEEK_API_KEY`. No Key file route, initialization,
repair, migration, reset or claim release is provided.

Exactly one request per case; 30 is the success denominator, never an instruction
to continue after failure. The cap 512 includes reasoning output. Input 61,440 and
cost 1 CNY are post-response stops, not per-request input or Provider-invoice caps.

Native status, normalized status, usage and response timing share a terminal audit
event. A subsequent case-close event links that record's hash and measures the
complete SDK request/client-cleanup interval. Independent replay checks both,
their order and the phase/sealing limits. Unknown or fallback is not native success.

## Privacy and artifacts

No request/response body, message/reasoning text, tool arguments, system prompt,
raw request ID, Key or Provider error text is logged. Provider-supplied error codes
are not trusted as safe diagnostics. Task text appears only in the approved task
file and its byte-identical archive copy; answer text (including ACK or nonempty
content) is not an acceptance criterion.

Internal JSON scans decoded keys/string values with the existing sensitive-content
scanner. This preserves rejection of true UNC/absolute paths and Unicode-escaped
secrets without mistaking JSON's escaped single backslash for a UNC path. The old
scanner is unchanged; SQLite still receives the raw-byte scan.

Output namespace: `output/internal-telemetry-v1/`. Work, archive and outer bundle
are exclusive and cannot overwrite any existing output. A completed archive has
the 12 files enumerated in `artifacts.FILES`; failures may retain only a prefix.

The invocation cannot certify its own exit. The independent reader needs the
expected bundle and approval digests plus separately observed exit status.
`offline_mock_transport` is explicitly distinguished from `native_http_transport`:
offline integration may pass engineering checks but never sets the online Internal
acceptance flag. Neither mode closes the old external milestone or T7.
